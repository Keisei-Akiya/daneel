# 0017: Void の導入

Status: Accepted (2026-11-24)

## 決定

- デプロイとビルドの基盤に Void（VoidZero）を使う。
- `apps/frontend` の Vite 設定に `voidPlugin()` を入れる。
- デプロイは CI（GitHub Actions）から `void deploy` で行う。
- 0013 の「デプロイの CLI は cf」を、この ADR で置き換える。
  `cf` と `@cloudflare/vite-plugin` は外し、`cloudflare.config.ts` は削除した。
- Void は Meta-Frameworks モードで使う。
  ルーティングと SSR は TanStack Start が担当し、Void は DB・KV・環境変数・マイグレーション・デプロイを担当する。
  Void 自身のルーティング（`pages/`、`*.server.ts`）と Void 管理の認証（`void/auth`）は使わない。
- Void の SDK（`void/db`、`void/kv`、`void/env`）も使う。
  スキーマは `apps/frontend/db/schema.ts`（D1、Drizzle）、環境変数は `apps/frontend/env.ts`、マイグレーションは `void db generate` で `db/migrations/` に出す。
  BFF（`apps/bff`）は `@schema` と `void/db`・`void/kv` を import して使う。
- Void は Node 24.22 以上を要求するため、`mise.toml` で Node 24 をプロジェクトに固定する。

## 理由

- Void は CI/CD 基盤として導入する。
- Void の役割は CI/CD 基盤であり、UI ライブラリとは関係がない。
  そのため、UI ライブラリ（Solid か React か）への対応の有無は、採用の判断材料にしない。

## 補足（アシスタントによる。ユーザーの言葉ではない）

- `void deploy` は、ビルド、D1/KV/R2 の作成、マイグレーション、Worker のアップロードを一括で行う。
  0013 の未決だった「D1 マイグレーションの自動適用」は、この `void deploy` に含まれる。
- 導入後の確認結果: `aube run build` と `tsc` が成功した（client / ssr / void_worker）。初期スキーマは conversations / messages の2表で、マイグレーションを1本生成した。
- Void は内部で `cf`（1.0.0-rc.0）と `@cloudflare/vite-plugin`（2.0.0-rc.0）に依存する（void@1.11.0 の `package.json`）。
  上の「外した」は、daneel の直接依存から外したという意味。
- Void の frameworks 対応表に載る TanStack Start のパッケージは `@tanstack/react-start`。Solid 版（`@tanstack/solid-start`）は表にない。
  ビルドは通っている。
- 未確認: `void deploy` の実行、`vite dev`、Hono との同居。実際のデプロイ時に確認する。
- CI に必要な secrets は `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID`。
  初回デプロイは1台で実行し、生成される `void.lock.json` をコミットしてから CI に任せる。
